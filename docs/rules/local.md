# ローカル環境規約

## 構成
- **Processing Unit**: Dockerコンテナで起動。
- **Middleware**: Dockerコンテナで起動。
- **Valkey**: Dockerコンテナで起動。Docker Compose のライフサイクル内で自動管理。

## ローカル環境起動手順
- ユーザーから明示的な起動指示があった場合のみ実行する（勝手に起動しない）。
- **起動前の前提条件（初回クローン時）：**
  1. **ツールセットアップ:** `make setup` を実行して、必要な開発ツール（Go, protocなど）をインストールします（miseが未インストールの場合、インストールスクリプトが案内されます）。
     - ※自動生成コード（`*.pb.go`）は、`make build` や `make up` 実行時に内部で `make proto` が自動的に走り、毎回最新の状態で生成されるため、個別にコマンドを実行する必要はありません。
- 起動手順：
  1. コンテナ停止: `make down` (または `docker compose down`)
  2. ビルド: `make build` (または `docker compose build`)
     - テストNG時はエラー詳細を出力して処理を中断。
  3. 起動: `make up` (または `docker compose up -d`)
  4. 確認: `docker ps` で `spacebase-processing` コンテナの起動を確認。
- 予期せぬエラー発生時は処理を中断し、エラー内容を報告すること。

## Valkey データの永続化
- ローカル開発環境では、コンテナ再起動や `make down` 時にもデータが失われないよう、物理ディスクへのボリュームマウント（AOF & RDB）が有効化されています。
- データの物理保存先は、プロジェクトルートにある `.env` ファイル内のプロパティ `VALKEY_DATA_DIR` で指定されています（デフォルトは `./data/valkey`）。
- 物理データ（`./data/`）およびローカル用の環境設定（`.env`）は `.gitignore` に追加されているため、Git にコミットされることはありません。
- 詳細および上位環境（本番 VM、Kubernetes 等）への適用方法については、`docs/valkey_persistence.md` を参照してください。

### Valkey データの初期化（手動削除）手順
開発中にデータを完全にクリーンな状態（初期状態）に戻したい場合は、以下のいずれかの方法を実行します。

#### 方法A：物理ファイルを直接削除して初期化する（推奨）
コンテナを一度停止し、ホスト側に保存されている物理データフォルダを削除して再起動します。この操作により、永続化データが完全にクリアされます。

1. コンテナを停止・削除：
```bash
make down
```

2. ホスト側の物理データフォルダを削除：
```bash
rm -rf ./data/valkey
```

3. コンテナを起動（空の状態で新規起動します）：
```bash
make up
```

#### 方法B：起動中にコマンドで全データを消去する
コンテナを起動したまま、Valkey の内部コマンドを実行してデータを一括クリアします（永続化ファイルも自動的にクリアされます）。

1. 以下のコマンドを実行して全データを消去（FLUSHALL）：
```bash
docker exec -it spacebase-valkey valkey-cli FLUSHALL
```
