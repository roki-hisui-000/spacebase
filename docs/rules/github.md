# GitHub連携・Git運用規約 (`github.md`)

## 1. 概要
本プロジェクトにおけるGitHub連携、Gitを用いたバージョン管理、およびPull Request（PR）のレビュー・運用ルールと手順を定義します。
不必要な大容量ファイルや環境依存 of ログファイルなどがリモートリポジトリに混入することを防ぎ、クリーンなリポジトリ状態を維持するとともに、**PRのレビュー時に古いコミットのキャッシュや以前のレビュー結果に依存せず、常に最新の変更内容（最新コミット/差分）を正確に参照して適切なレビューを行うこと**を目的とします。

## 2. リポジトリ情報
- **リモートURL**: `https://github.com/roki-hisui-000/spacebase`
- **デフォルトブランチ**: `main`

## 3. Git管理の除外ルール（`.gitignore`）
以下のファイルはGitの管理対象外（プッシュ禁止）としています。新規追加された同種ファイルも対象外としてください。
- **実行バイナリ**: `processing`, `server` などのビルド済みバイナリ（容量が大きく競合の原因となるため）
- **ログファイル**: `build.log` やその他 `*.log` ファイル
- **一時ファイル**: `-cli ping` などのCLIテスト用の一時ファイル

## 4. 推奨開発・運用フロー

### ステップ1: ステータスの確認
ステージング（Gitへの追加待ち）されているファイルや、新しく作成されたファイルを確認します。
```bash
git status
```

### ステップ2: 変更内容の追加 (ステージング)
必要なファイルのみが追加されることを確認します（`.gitignore` により、バイナリやログは自動で除外されます）。
```bash
git add .
```

### ステップ3: コミットの作成
何を変更したかが分かりやすい簡潔なコミットメッセージを作成します。
```bash
git commit -m "feat: <実装した機能や変更内容>"
```

### ステップ4: GitHubへの反映 (PUSH)
`main` ブランチに対して変更をプッシュします。
```bash
git push origin main
```

## 5. 認証に関するトラブルシューティング

### Q. `git push` 時にタイムアウトや認証エラーになる場合
GitHubへの認証（ユーザー名・パスワード・アクセストークン等）が切れている、あるいは未認証の状態です。以下の対策を行ってください。

1. **Personal Access Token (PAT) を使用する**
   HTTPSプロトコル経由でプッシュする際、パスワードの代わりにGitHubで発行した「Personal Access Token」を入力するか、以下のコマンドで認証情報をリモートURLに埋め込んでください：
   ```bash
   git remote set-url origin https://<YOUR_TOKEN>@github.com/roki-hisui-000/spacebase
   ```
2. **GitHub CLI (`gh`) を使用して再ログインする**
   ```bash
   gh auth login
   ```
### AIエージェント（Cline）への指示
1. 今後、AIエージェントが自動でGit操作やコミット、プッシュを行う場合は、必ず本規約（`github.md`）に記載されている手順および `.gitignore` の設定を遵守すること。
2. **テンプレートの遵守**: IssueやPull Requestを作成、またはその本文を提案・下書きする際は、必ずリポジトリ内の `.github/pull_request_template.md` および `.github/ISSUE_TEMPLATE/` 以下の各種テンプレート（`bug_report.md` / `feature_request.md`）のフォーマットと項目に厳格に準拠すること。
3. **最新コミット・差分の厳格な確認（PRレビュー・修正確認時）**:
   PRのレビューや修正内容の確認を行う際、過去のレビュー履歴や古いコミットのキャッシュのみに基づいてレビューを行わないこと。必ず以下の手順に従い、最新の変更を正確に反映したレビューを実施してください。
   - レビュー開始前に、最新のブランチ状態をリモートから取得（`git fetch origin` など）し、レビュー対象のコミットハッシュ（SHA）が最新であることを確認する。
   - 前回指摘した内容への修正が行われているかを確認する際は、該当コミットまたはPRの最新の差分（`git diff` や GitHub上の最新のファイル変更内容）を直接取得し、コードが実際に更新されているかを検証する。
   - 過去の指摘を単に繰り返すのではなく、最新コミットにおけるコードベース全体を毎回フレッシュに解析する。
4. **トークン使用量の軽減（コンテキスト最適化）**:
   PRレビューやファイル読み込みを行う際は、トークン消費量を最小限に抑えるため、以下の最適化ルールを徹底すること。
   - **差分のみにフォーカス**: レビュー対象を `git diff` などで変更が検知されたファイルのみに限定し、プロジェクト全体の無関係なファイルを不必要に読み込まない。
   - **不要なファイルの除外（フィルタリング）**: 自動生成ファイル（`*.pb.go` 等）、依存関係のロックファイル（`go.sum`, `package-lock.json`, `pnpm-lock.yaml` 等）、画像やバイナリなどの非コードファイルは読み込み対象から完全に除外する。
   - **部分読み込みの徹底**: 変更があったファイルが非常に大きい場合、ファイル全体を丸ごと読み込むのではなく、変更箇所およびその周辺行（`start_line` / `end_line`）のみを指定してピンポイントで読み込む。
   - **優先度付け**: 変更差分が極端に大きい場合、ビジネスロジックやコア設定の変更箇所を優先的にレビューし、テストコードやコメント・ドキュメントの微細な修正は必要最小限のトークンで処理する。
