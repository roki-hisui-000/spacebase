# アーキテクチャ・設計思想

## プロジェクト概要
- Go言語によるスペースベースアーキテクチャ。仮想ミドルウェアと処理ユニット（Processing Unit）で構成。
- AIエージェントは以下のルールと制約を「Skill」として理解し、開発作業を正確に実行すること。

## システム構成
- **Middleware**: HTTPリクエストを受け付け、内部でgRPCを用いてProcessing Unitと通信。
- **Processing Unit**: gRPCサーバーとして動作し、受信データをValkey（永続化）に保存。
- **Valkey**: Redis互換インメモリデータストア。ホスト上で稼働 (`127.0.0.1:6379`)。

## ネットワーク・インフラ制約
- **Hostネットワークモード**: 全Dockerコンテナは `network: host` で動作。
- コンテナ間およびValkeyへの通信はすべて `localhost`（`127.0.0.1`）経由で行うこと（ブリッジ/独自ネットワークは使用禁止）。

## 開発ポリシー
- **最小安全実装**: 既存のインターフェースや設定の互換性を壊さない最小限のコード追加・リファクタリングに留める。
- **設定管理**: `config/config.dev.yaml` 等のYAMLファイルで環境別設定を管理。環境変数との整合性に注意する。
- **gRPCスキーマ変更**: `proto/processing.proto` を変更した場合は、必ず Go コードを再生成すること。
