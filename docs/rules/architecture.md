# アーキテクチャ・設計思想

## プロジェクト概要
- Go言語によるスペースベースアーキテクチャ（仮想ミドルウェア + Processing Unit）。
- AIエージェントは本ルールを「Skill」として理解し、開発作業を正確に実行すること。

## システム構成
- **Middleware**: 
  - 外部からのHTTPリクエストを受付。内部でgRPCを用いてProcessing Unitと通信。
  - Processing Unit向けに、抽象化されたデータスペース（タプルスペース）操作用のgRPCサービス（`SpaceService`）を提供。
  - 本システム内で唯一、データベース（Valkeyなどの永続化ストア）と物理的に接続し、データの永続化と取得を行う。
- **Processing Unit**: 
  - ビジネスロジックを処理するgRPCサーバー。
  - 物理的なデータベースへの直接の接続は持たず、データの永続化や取得は、すべてMiddlewareが提供する `SpaceService` を経由して行う。
- **Valkey**: 
  - Redis互換インメモリデータストア。データスペース（永続化/共有メモリ）のバックエンドとして動作。

## ネットワーク・インフラ制約
- 全コンテナはホストネットワークモード (`network: host`) で動作。
- コンテナ間、データベース、および各種gRPC通信の接続先（アドレス、ポート）は、すべて環境変数または設定ファイルを通じて動的に設定され、個別ネットワーク空間を介さずに接続可能とする。

## 開発・行動指針
- **最小限の実装**: コード追加・リファクタは常に最小限とし、既存の互換性を維持する。
- **設定ファイル**: 環境別設定は `config/config.dev.yaml` 等で管理。環境変数との整合性に注意。
- **gRPCスキーマ変更**: `proto/processing.proto` 変更時は、必ず `make generate` 等で Go コードを再生成すること。
