# [ダッシュボード作成] シミュレータ設計・仕様

[issue](https://github.com/roki-hisui-000/spacebase/issues/32)

## 概要
管理者ダッシュボードのリアルタイム性をテスト・確認するために、バックエンドの永続化API（`POST /api/dashboard/orders`）に擬似的な注文リクエストを指定された頻度で送信し続けるシミュレータです。

## シミュレータ仕様
シミュレータは独立したコンテナ（`simulator`）として動作し、指定された間隔（ミリ秒）で自動的に注文データを生成してミドルウェアに送信します。

### 1. 接続先API
- **URL**: `${API_URL}` （デフォルト: `http://middleware:8080/api/dashboard/orders`）
- **Method**: `POST`

### 2. 生成データルール
シミュレータが送信する各リクエストボディの項目は、以下のように半ランダムで生成されます。
- `userId`: `user_<1〜100のランダム値>`
- `price`: `100〜2000` のランダムな数値（50刻み、例: 150, 450, 1200）
- `status`: 以下のステータスからランダム（重み付けあり）で選択
  - `completed` (注文完了): 70%
  - `order` (注文受付): 15%
  - `reject` (拒否): 10%
  - `error` (エラー): 5%
- `requestId`: `req_<UUIDv4形式またはランダム文字列>`

```json
{
  "userId": "user_42",
  "price": 150,
  "status": "completed",
  "requestId": "req_89a3f2d1"
}
```

## コンテナ構成と環境変数

シミュレータの動作は、以下の環境変数で柔軟に変更することができます。

| 環境変数名 | 説明 | デフォルト値 |
| --- | --- | --- |
| `API_URL` | シミュレータが叩く永続化APIのエンドポイントURL | `http://middleware:8080/api/dashboard/orders` |
| `INTERVAL_MS` | APIを呼び出す頻度（ミリ秒単位）。例えば 1000 で1秒に1回、200 で1秒に5回。 | `1000` |
| `ENABLED` | シミュレータを有効化するかどうか (`true` / `false`) | `true` |

### 障害耐性・リトライロジック
コンテナ起動時にミドルウェア（APIサーバー）がまだ完全に起動していない可能性があるため、最初の接続に失敗した場合は **5秒おきにリトライ** を行い、正常に接続できるようになるまで待機します。

## 起動方法（待機・手動キック型）
本シミュレータは `docker compose up` のデフォルト起動（一括起動）からは除外されています。
必要な時に、ホストマシンから個別のコマンドを送信して、シミュレータを「キック」して動作させることができます。

### 1. `Makefile` を使った一番簡単なキック方法
プロジェクトルートで `make run-simulator` コマンドを実行します。
（内部的に `docker compose run --rm` コマンドが走り、用が済んだら自動的にコンテナが削除されます）

```bash
# 標準設定（無限に送信、1秒間隔）でシミュレータをキック
make run-simulator

# 【おすすめ】 500ms間隔で10件だけ注文を送信して自動終了させる
make run-simulator COUNT=10 INTERVAL=500
```

### 2. `docker compose` コマンドを直接使うキック方法
より詳細なフラグを渡してキックしたい場合は、以下のコマンドを直接実行します。

```bash
# 200ms間隔で50件送信して自動終了
docker compose run --rm simulator -interval=200 -count=50

# ヘルプ（設定可能なオプション一覧）を表示
docker compose run --rm simulator -help
```

### ログの確認方法
手動でキックした場合、実行ログはコンソールに直接リアルタイムで出力されます。
もしバックグラウンドで起動したい場合は `-d` フラグを挟んで起動することも可能です。
